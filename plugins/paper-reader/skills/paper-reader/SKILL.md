# Paper reader

Produces a private claude.ai artifact for reading one paper. The reader shell (`template.html`) encodes choices Will made and tested; keep them unless he asks otherwise:

- Body text in Atkinson Hyperlegible Next by default, line height 1.5, 18px, about 66 characters per line. A reading-settings menu ("Aa") switches font (Sans / Hyperlegible / Serif), size (16–20px), line length and theme, saved per browser.
- Headings in Source Serif 4. Captions in the body font, higher contrast than muted text.
- The text column is centred in the content area. Figures, interactive widgets and display equations may use the full content column, wider than the text; equations and tables are centred on the same axis as the text, with equation numbers at the right.
- Light and dark themes. In dark mode, figures that are line art (mostly white, little color: diagrams, plots) are inverted with their hues kept, so they sit on the dark page; color-carrying figures (heatmaps, colormaps, photos) stay on a dimmed light plate. `common.figure_tone` sorts them at build time (thresholds tuned on 51 figures); a click on a figure in dark mode switches it to its original colors, remembered per figure. Interactive widgets with hard-coded light colors sit on a light plate.
- Citations, footnotes, and references to figures, tables and equations preview in popovers.

## arXiv papers

Most arXiv papers have an HTML version (arxiv.org/html/<id>, generated by LaTeXML). Convert it:

```
uv run "${CLAUDE_PLUGIN_ROOT}/skills/paper-reader/arxiv.py" <id or arxiv URL> --out <dir>
```

Use a session scratch directory for `--out` unless Will names a place. The script prints the equation, image and footnote counts and the number of publish batches. If it says there is no HTML version, the paper only has a PDF; tell Will, and offer the PDF route below.

Then take one look in a browser (serve `<dir>` with `python3 -m http.server` and open it), checking:
- equations: count `[data-tex].tex-fallback` (equations KaTeX could not parse, showing the browser's MathML instead). A few is fine; many means a missing macro — add it to `macros` in `template.html`.
- raw LaTeX in the text (LaTeXML marks unconverted commands `.ltx_ERROR`; the converter removes them, but check for other leftovers).
- figures load, lists and tables look right, and the page does not scroll sideways.

## Blog posts and other web pages

No general converter: sites differ too much. Procedure:

1. Have Will save the page with the browser's "Save Page As…, complete" (gives `<name>.html` and a `<name>_files` folder), or fetch it if it is static.
2. Find the article element and extract it with BeautifulSoup. Drop site navigation, banners, cookie notices and footers.
3. Map its parts onto the shell's slots (below): sections become `h2`/`h3` with ids, footnotes and references become `.endnotes` lists with `.poppable` items, figures keep their images (copy them into `figures/`).
4. Interactive figures: check whether the page's own JavaScript can run inside the artifact. If it fetches data from another host, download that data and serve it from the artifact. A worked example with everything this involved (Goodfire's VPD post: widget code, 203 data files, a fetch shim, a width cutoff patch) is `explainers/vpd-reader/build.py` in Will's `mats-research` repo.

Write the converter as a script in the session (or in the relevant repo if the page will be rebuilt), importing `fill` and `write_batches` from `common.py` in `${CLAUDE_PLUGIN_ROOT}/skills/paper-reader/`.

## PDFs

Not automated. Try, in order: an HTML version of the same paper (arXiv, the venue's site, the authors' site), then text extraction with the `pdf` skill, accepting that equations and figures will need hand-fixing. Tell Will the result will be rougher before starting.

## The shell's slots

`common.fill(**slots)` returns `template.html` with these filled (unfilled slots become empty):

| Slot | Content |
|---|---|
| `TITLE` | Paper title (also the page `<title>`) |
| `EYEBROW` | Small line above the title, e.g. `arXiv 2501.14926v4 · reading copy` |
| `BYLINE` | `<p class="authors">…</p>`, optional `<p class="affil">…</p>` lines; include a link to the original |
| `TOC` | `<ul class="toc-list">` of `<li class="toc-group">` (add ` toc-appendix` for appendices) with an `<a href="#id">` and an optional nested `<ul class="toc-sub">` |
| `BODY` | The article; an `<div class="abstract"><span class="label">Abstract</span>…</div>` first if there is one |
| `ENDNOTES` | `<section class="endnotes" id="footnotes">` / `id="references"` with an `<h2>` and a list |
| `EXTRA_CSS`, `EXTRA_JS` | Source-specific styles and scripts (`latexml.css` for arXiv) |

Conventions the shell relies on: math as `<span data-tex="…" data-display="1|0">fallback</span>` (rendered by KaTeX at load); display equation blocks as `<table class="eq">` rows with a `td.eq-no`; any element an in-page link should preview gets class `poppable`; wide tables go in `<div class="table-scroll">`.

## Publishing

Load the `artifact-design` guidance as usual; the shell already satisfies it (title, theme tokens, CDN rules, phone layout).

- Publish `<dir>/index.html` as a private artifact (icon `book`), with the files from the first list in `<dir>/batches.json` as `files` and `root` set to `<dir>`. Publish each later list to the same artifact (same file path, or its `url`). The host allows at most 64 MB and 255 files per publish and 256 MB per artifact.
- The host serves only standard web types: no `.gz`, no arbitrary binaries. Compress large JSON as base64 text of gzip (`.gz.txt`) and decode it in the page (see the VPD example).
- The claude.ai viewer frames the page narrower than the window, often under 900px on a laptop. Width-based cutoffs in a page's own code may need lowering.
- Pages cannot fetch from other hosts at runtime, and stylesheets and fonts load only from Google Fonts (KaTeX's fonts are inlined by `common.katex_css`).
- These are private copies of other people's work for Will's own reading: keep the original's credit and a link in the byline, leave out the source site's branding, and never share them.
- If Will wants a reader kept with a project, put the converter (not the built output) in that repo with a README line linking the artifact, as in `mats-research/explainers/`.
